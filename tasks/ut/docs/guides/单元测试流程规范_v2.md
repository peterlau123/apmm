### 1.3 选择待执行批次

## 二、测试中（执行阶段）

### 2.1 执行 pytest

```bash
# 远程执行（通过 agent.py）
python agent.py -p t_h20 run --timeout 600 "
  sudo docker exec v0.13.0_torch2.5.1_ut bash -c '
    cd /gpfs/gcsp/M2.7_verify/vllm
    pytest -q --tb=long tests/xxx.py 2>&1 | tee ut_logs/batch_20260609_1000.log
  '
"
```

**pytest 参数说明**:
- `-q`: 简洁输出
- `--tb=long`: 详细错误堆栈
- 排除不支持的平台（见 AGENTS.md）

### 2.2 监控执行状态

- 每 5 分钟检查日志进度
- 记录中途失败/错误的测试
- 处理超时或中断情况

```bash
cd D:/workspace/apmm/tasks/ut/test_analysis/scripts
python update_test_load.py --batch batch_results.json
```

### 3.3 标记版本错配（如有）

```bash
# 对于 vllm+torch 版本相关的错误
python update_test_load.py \
  --test "tests/xxx.py::test_func" \
  --status error \
  --version-mismatch \
  --error-message "torch version mismatch: expected 2.5.1, got 2.7.0"
```

### 3.4 验证更新结果

```bash
python update_test_load.py --report
```

## 四、每日定时任务

### 4.1 Cronjob 配置

| 时间 | 任务 | 脚本 | 输出 |
|------|------|------|------|
| **18:00** | 更新PROGRESS.md + 生成报告 | `ut_daily_reports.py` | 飞书 + 本地文件 |
| **20:00** | 每日统计 | `ut_daily_stats.py` | 飞书 |

### 4.2 18:00 任务详情

**执行内容**:
1. 更新 `tasks/ut/PROGRESS.md`（头部插入统计块）
2. 生成 `测试报告_<时间戳>.md`
3. 生成 `失败分析报告_<时间戳>.md`

**文件命名格式**:
- `测试报告_20260609_180000.md`
- `失败分析报告_20260609_180000.md`

**报告位置**: `test_analysis/reports/`

### 4.3 20:00 任务详情

**执行内容**:
- 生成 JSON 格式统计报告
- 发送到飞书群

## 五、文件结构

```
test_analysis/
├── manifest.json              # ★ 测试状态主文件（唯一数据源）
│   ├── statistics             # 统计信息
│   │   ├── total              # 用例总数
│   │   ├── executed           # 已执行数
│   │   ├── progress           # 进度百分比
│   │   ├── passed/failed/error/pending/todo
│   └── tests[]                # 测试用例数组
│       ├── test_node          # 测试节点 ID
│       ├── status             # 状态
│       ├── error_message      # 错误信息
│       ├── failed_message     # 失败信息
│       ├── version_mismatch_related  # 版本错配标记
│       ├── run_at             # 执行时间
│       ├── duration_ms        # 执行时长
│       └── log_file           # 日志路径
│
├── reports/                   # 每日报告目录
│   ├── 测试报告_<时间戳>.md
│   └── 失败分析报告_<时间戳>.md
│
├── scripts/
│   ├── update_test_load.py     # ★ 状态更新脚本
│   ├── generate_daily_reports.py  # 报告生成脚本
│   ├── merge_phases.py        # Phase合并脚本
│   └── add_missing_fields.py  # 字段补充脚本
│
└── archive/                   # 历史备份
```

## 六、脚本命令汇总

```bash
# === 状态更新 ===
python update_test_load.py --batch results.json     # 批量更新
python update_test_load.py --test "xxx" --status failed  # 单个更新
python update_test_load.py --recalc-stats           # 重新计算统计
python update_test_load.py --report                 # 文本报告
python update_test_load.py --daily-report           # JSON报告（飞书用）

# === 每日报告 ===
python generate_daily_reports.py                   # 生成所有报告

# === Phase合并（一次性）===
python merge_phases.py                             # 合并phase1+phase2
```

## 七、状态字段说明

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `status` | string | pending | passed/failed/error/pending/todo |
| `error_message` | string | null | 错误信息（pytest ERROR） |
| `failed_message` | string | null | 失败信息（pytest FAILED） |
| `version_mismatch_related` | bool | false | 是否与vllm+torch版本错配有关 |
| `run_at` | datetime | null | 执行时间 |
| `duration_ms` | int | null | 执行时长（毫秒） |
| `exit_code` | int | null | pytest 退出码 |
| `log_file` | string | null | 日志文件路径 |
