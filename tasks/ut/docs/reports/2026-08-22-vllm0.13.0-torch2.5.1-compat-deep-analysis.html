1.2.1 marlin 算子缺失根因证据链（已验证）

1️⃣ 现象：NotImplementedError: Could not run '_C::gptq_marlin_gemm'（479）+ repack（292）+ opcheck（64）≈ 841 条
2️⃣ 二进制符号：nm -D vllm/_C.abi3.so | grep -ic marlin → 0 个 marlin 符号
3️⃣ 构建配置：CMakeCache.txt 中 CMAKE_CUDA_ARCHITECTURES:STRING=52（sm_52），marlin 编译条件为 MARLIN_ARCHS = 8.0+PTX ∩ CUDA_ARCHS → 交集为空，marlin 0 个编译
4️⃣ H20 架构：nvidia-smi 显示 H20 compute_cap = 9.0（sm_90），在 marlin 支持范围内 → 芯片支持但构建产物缺失
5️⃣ 佐证：_moe_C.abi3.so 8/7 重编后 moe marlin 失败从大量降至 4 条 → 重新编译即可解决
✅ 结论：非芯片问题，是构建 arch 配置错误。修复 = TORCH_CUDA_ARCH_LIST="9.0" 重新编译，收益 841 条

1.2.2 triton_key 接口不兼容证据链（已验证）

1️⃣ 现象：ImportError: cannot import name 'triton_key' from 'triton.compiler.compiler'（495 + 24 条）
2️⃣ 实测复现：容器内 from triton.compiler.compiler import triton_key → 同样 ImportError
3️⃣ 环境：容器 triton 3.5.0，python3.12
✅ 归因：triton 版本与 vllm 0.13.0 不配套（接口已重构），非芯片问题。修复：锁配套 triton 版本或 patch 接口

1.2.3 torch 2.5.1 能力边界（FP8 不完整）

• cat_cuda not implemented for 'Float8_e4m3fn'（225 条）：torch 2.5.1 cat 内核不支持 FP8，集中在 test_batched_moe.py(192)
• module 'torch' has no attribute 'float8_e8m0fnu'（80 条）：E8M0 格式为 torch 2.7+ 新增，vllm 0.13.0 代码已引用 → 直接证明 vllm 0.13.0 开发基线高于 torch 2.5.1
• 这两类合计 305 条，是「torch 2.5.1 已落后于 vllm 0.13.0」的硬证据，FP8 是 H20 关键能力

3. 除兼容性问题外需要关注的问题

  1. 构建链 arch 配置错误（最优先）：_C.abi3.so 用 sm52 编译致 marlin 内核全缺失 —— 构建/发布流程缺陷，不升级 torch 也应修复（重编即得 841 条）
  2. triton 版本锁定缺失：容器 triton 3.5.0 与 vllm 0.13.0 不配套，建议环境声明锁定匹配版本
  3. HF 模型离线准备不完整：29 个模型缺失致 ~1,300 条失败；gated 模型需授权，未授权用 model_replacement.py 替换
  4. executor timeout 机制：1,787 条连坐中 detokenize 902；需区分真超时（用例慢）vs 假超时（executor 层）
  5. 多卡测试环境：17 条需多机，单机无法覆盖 —— 环境限制
  6. retriable_error 命令构造 bug：3 条因单引号被 bash -c 破坏 —— apmm 框架缺陷
  7. GPU1 硬件异常残留：历史 Xid31 已 exclude_gpus=[1] 规避；本轮 8 条 cuDNN 需在健康卡上复验

5. 报告小结：兼容问题总体评估与升级建议

总体评估
通过率 26,875/32,955 = 81.5%；非 passed 6,080 中核心兼容性问题 2,122（34.9%）。兼容性问题非芯片问题：marlin 构建缺失（arch 配置错误）+ triton 版本不配套 + torch 2.5.1 能力边界（FP8 不完整）。
可救性：兼容性问题中 easy 修复 ~1,043（49%）· medium ~550 · difficult ~80；环境类 1,301 补模型缓存即救；timeout 1,787 重跑可救。
是否升级 torch？—— 建议：有条件地升级，或至少先修复构建问题
支持升级（torch 2.6+/2.7+）：① vllm 0.13.0 已引用 torch 2.7+ API（float8_e8m0fnu 80 条）；② torch 2.5.1 FP8 支持不完整（cat_cuda 225 条），而 FP8 是 H20 关键能力；③ 上游 vllm main 已要求 torch 2.11.0，长期停留 2.5.1 无法跟进上游；④ triton 配套问题在旧版本矩阵更难对齐。
支持暂不升级：① marlin 841 是构建问题非版本问题，重编即可；② 环境 1,301 + timeout 1,787 + 可重试 5 ≈ 3,093 条与 torch 版本无关；③ 若目标芯片已有 2.5.1 配套算子适配，升级需全量重验证。

行动建议（优先级排序）

优先级行动预计收益
P0用 TORCH_CUDA_ARCH_LIST="9.0" 重新编译 vllm 扩展（修复 marlin）+841 条
P0锁定/安装与 vllm 0.13.0 配套的 triton（或 patch triton_key）+519 条
P1补齐 HF 模型缓存（含 gated 授权）或用替代模型+~1,300 条
P1修复 executor timeout 机制（区分真假超时）+~1,500 条
P2评估 torch 2.6/2.7 升级（重点验证 FP8：cat_cuda/float8_e8m0fnu）+~305 条
P2人工处理留存 ~690-790 条（断言/空消息/杂项）定性收尾
一句话结论
vllm 0.13.0 + torch 2.5.1 在 H20 上的兼容性问题：约 1/3 是构建与版本配套缺陷（可低成本修复），约 1/4 是 torch 2.5.1 自身能力边界（FP8 不完整、缺 2.7 API）。若目标芯片对 FP8 有硬需求，建议升级 torch 至 2.6+（或跟随 vllm 官方版本）；无论是否升级，都需先修复 marlin 构建问题。
